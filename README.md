# C言語単体テスト自動生成ツール

C言語の関数から、Unity単体テストフレームワークを使用した単体テストを自動的に生成するPythonツールです。MC/DC 100%カバレッジの真偽表とUnityテストコード、Input/Output一覧表を生成します。

## 特徴

- **MC/DC 100%カバレッジ**: Modified Condition/Decision Coverage を満たすテストケースを自動生成
- **Unity単体テスト対応**: Unity単体テストフレームワークのコードを自動生成
- **Excel真偽表生成**: if文の条件式から真偽表をExcelファイルで出力
- **モック/スタブ生成**: 呼び出し回数カウント機能付きのモック・スタブ関数を自動生成
- **Input/Output一覧表**: 各テストケースの入出力変数を管理するExcel表を生成

## 使用方法

### 基本的な使い方

```bash
python src/main.py <Cソースファイル> [オプション]
```

### コマンドラインオプション

- `c_file`: テスト対象のCソースファイルのパス（必須）
- `-f, --function <関数名>`: テスト対象の関数名（省略時は全ての関数が対象）
- `-o, --output-dir <ディレクトリ>`: 出力ディレクトリのパス（デフォルト: ./output）
- `-v, --verbose`: 詳細な出力を表示
- `-h, --help`: ヘルプメッセージを表示

### 使用例

#### 例1: 特定の関数に対してテストを生成

```bash
python src/main.py test/22_obfuscated.c --function Utf1 --output-dir ./output
```

#### 例2: ファイル内の全ての関数に対してテストを生成

```bash
python src/main.py test/22_obfuscated.c --output-dir ./output
```

#### 例3: カレントディレクトリに出力

```bash
python src/main.py test/22_obfuscated.c --function Utf1
```

## 出力ファイル

ツールは以下の3種類のファイルを生成します：

### 1. Excel真偽表 (`<関数名>_truth_table.xlsx`)

MC/DC 100%カバレッジを満たすテストケースの真偽表です。

| No. | 真偽 | 判定文 | 期待値 |
|-----|------|--------|--------|
| 1   | T    | if ((f4() & 0xdf) != 0) | v9が7 |
| 2   | F    | if ((f4() & 0xdf) != 0) | v9!=7 |
| 3   | TF   | if ((mx63 == m47) \|\| (mx63 == m46)) | |
| 4   | FT   | if ((mx63 == m47) \|\| (mx63 == m46)) | |
| 5   | FF   | if ((mx63 == m47) \|\| (mx63 == m46)) | |

**真偽値の読み方:**
- `T`: True（条件が真）
- `F`: False（条件が偽）
- `TF`: 複合条件の場合、左から順に真偽値を表す
  - 例: `TF` = 左の条件がTrue、右の条件がFalse

### 2. Unity単体テストコード (`test_<関数名>.c`)

Unity単体テストフレームワークのテストコードです。以下の内容を含みます：

- テスト関数のプロトタイプ宣言（static）
- モック/スタブ関数の実装（呼び出し回数カウント付き）
- 各テストケースのテスト関数
- setUp/tearDown関数

**テスト関数の命名規則:**
```
test_<テスト番号>_<判定文>_<真偽値>
```

例: `test_03_mx63_eq_m47_TF`

**生成されたコードのTODO:**
1. モック/スタブの戻り値を適切に設定
2. テストの期待動作をコメントに記載
3. アサーションを追加
4. テスト対象関数の実装をファイル末尾にコピー

### 3. Input/Output一覧表 (`<関数名>_io_table.xlsx`)

各テストケースの入出力変数を管理するExcel表です。

| No | テスト名 | INPUT列... | OUTPUT列... |
|----|----------|-----------|-------------|
| 01 | test_01_... | - | - |
| 02 | test_02_... | - | - |

**使い方:**
- INPUT列に各テストケースの入力値を記入
- OUTPUT列に各テストケースの期待出力値を記入
- ケアしない変数は `-` のまま

## 仕様詳細

### MC/DC (Modified Condition/Decision Coverage)

MC/DC 100%カバレッジを満たすため、以下のルールでテストケースを生成します：

#### OR条件 (`||`)
2つの条件 `A || B` の場合:
- TF: Aが真、Bが偽 → 結果は真
- FT: Aが偽、Bが真 → 結果は真
- FF: 両方偽 → 結果は偽

#### AND条件 (`&&`)
2つの条件 `A && B` の場合:
- TT: 両方真 → 結果は真
- TF: Aが真、Bが偽 → 結果は偽
- FT: Aが偽、Bが真 → 結果は偽

#### 複雑な条件
3つ以上の条件や、ANDとORが混在する場合は、各条件が独立して結果に影響を与えることを示すテストケースを生成します。

### テストコード生成の特徴

1. **プロトタイプ宣言**: モック、スタブ、テスト関数は全て`static`宣言
2. **呼び出し回数カウント**: モック/スタブは呼び出し回数をカウントし、`TEST_ASSERT_EQUAL`で監視
3. **境界値テスト**: 大小関係の比較は境界でテスト
   - 例: `if (v10 > 30)` の場合、T: v10=31、F: v10=30
4. **#if定義考慮**: 各定義でコンパイルが通るようコメントで注意喚起
5. **実質来ないテストは除外**: 例: 1bitの変数で`case 0, case 1, default`がある場合、defaultは不要

## 制限事項と今後の拡張

### 現在の制限事項
1. プリプロセッサマクロの完全な展開は未対応
2. 関数ポインタや複雑な型の完全な解析は未対応
3. switch文の真偽表生成は基本的な対応のみ
4. モック/スタブの戻り値型は手動調整が必要

### 今後の拡張可能性
- より高度なC言語パーサー（pycparserライブラリの完全活用）
- switch文の完全なMC/DCカバレッジ対応
- 自動的な型推論とモック生成
- GUIインターフェース
- テスト実行とカバレッジ測定の統合
